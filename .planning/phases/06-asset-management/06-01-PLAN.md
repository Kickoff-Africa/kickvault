**assets.validation.ts** -- Mirror credentials.validation.ts pattern:

```typescript
export const createAssetSchema = z.object({
  assetId: z.string().min(1).max(100),
  name: z.string().min(1).max(255),
  category: z.enum(['HARDWARE', 'SOFTWARE', 'DIGITAL', 'INTANGIBLE']),
  status: z.enum(['ACTIVE', 'MAINTENANCE', 'RETIRED', 'LOST']).optional(),
  location: z.string().max(500).optional(),
  notes: z.string().max(2000).optional(),
});

export const updateAssetSchema = z.object({
  name: z.string().min(1).max(255).optional(),
  category: z.enum(['HARDWARE', 'SOFTWARE', 'DIGITAL', 'INTANGIBLE']).optional(),
  status: z.enum(['ACTIVE', 'MAINTENANCE', 'RETIRED', 'LOST']).optional(),
  location: z.string().max(500).nullable().optional(),
  notes: z.string().max(2000).nullable().optional(),
}).refine(
  (data) => Object.values(data).some(v => v !== undefined),
  { message: 'At least one field must be provided' },
);
```

IMPORTANT: `assetId` is NOT in `updateAssetSchema` -- it cannot be changed after creation.

Export `CreateAssetInput` and `UpdateAssetInput` types.

**assets.service.ts** -- Mirror credentials.service.ts but with these differences:

1. No encryption (assets have no secrets).
2. Add `validateStatusTransition` function:
   - `VALID_TRANSITIONS` map: ACTIVE->[MAINTENANCE, RETIRED, LOST], MAINTENANCE->[ACTIVE], LOST->[ACTIVE, RETIRED], RETIRED->[] (terminal)
   - Same status (current === next) is a no-op, always allowed
   - SUPER_ADMIN can force any transition OUT of RETIRED
   - Throws `ValidationError('Cannot transition asset from ${current} to ${next}')` on invalid transition

3. `SAFE_ASSET_SELECT` includes all non-sensitive fields: id, assetId, name, category, status, location, notes, createdById, createdAt, updatedAt.

4. Service functions:
   - `createAsset(data, createdById)`: prisma.asset.create with SAFE_ASSET_SELECT, catch P2002 -> ConflictError('Asset ID already exists'), then grantAssetAccess(asset.id, createdById, MANAGE), then createAuditLog(userId=createdById, action='CREATE', targetType='ASSET', targetId=asset.id). Return asset.
   - `listAssets(userId, userRole)`: Same scoping pattern as credentials (privileged sees all non-deleted, others see only access-granted). Use `access: { some: { userId } }` (NOT `assetAccess` -- the Prisma relation name is `access`).
   - `getAsset(id, userId, userRole)`: checkAssetAccess(VIEW), findFirst where id + deletedAt null, throw NotFoundError if null.
   - `updateAsset(id, data, userId, userRole)`: checkAssetAccess(EDIT), findFirst to get existing, throw NotFoundError if null, if data.status !== undefined call validateStatusTransition(existing.status, data.status, userRole), then prisma.asset.update with SAFE_ASSET_SELECT. createAuditLog action='UPDATE'. Return updated asset.
   - `deleteAsset(id, userId, userRole)`: checkAssetAccess(MANAGE), findFirst, throw NotFoundError if null, soft delete (set deletedAt), createAuditLog action='DELETE'.

Imports: PermissionLevel from @prisma/client, checkAssetAccess from requireResourceAccess, grantAssetAccess from asset-access.service, createAuditLog from audit.service, NotFoundError/ValidationError/ConflictError from errors. All imports use .js extension (ESM).

encrypt/decrypt are NOT needed -- assets have no encrypted fields.
