    **1. Create src/modules/auth/auth.validation.ts:**

    Zod schemas for request body validation:

    ```typescript
    import { z } from 'zod';

    export const loginSchema = z.object({
      email: z.string().email(),
      password: z.string().min(1),
    });

    export const refreshSchema = z.object({
      refreshToken: z.string().min(1),
    });

    export const forgotPasswordSchema = z.object({
      email: z.string().email(),
    });

    export const resetPasswordSchema = z.object({
      token: z.string().min(1),
      password: z.string().min(12, 'Password must be at least 12 characters'),
    });

    export type LoginInput = z.infer<typeof loginSchema>;
    export type RefreshInput = z.infer<typeof refreshSchema>;
    export type ForgotPasswordInput = z.infer<typeof forgotPasswordSchema>;
    export type ResetPasswordInput = z.infer<typeof resetPasswordSchema>;
    ```

    **2. Create src/modules/auth/auth.service.ts:**

    Business logic layer. All functions take explicit parameters (no req/res). Import `hashToken` from token.service.ts for ALL SHA-256 hashing. Do NOT import crypto directly.

    ```typescript
    import { signAccessToken, generateRefreshToken, generateResetToken, hashToken } from '../../services/token.service.js';
    import { verifyPassword, hashPassword } from '../../services/password.service.js';
    import { sendPasswordResetEmail } from '../../services/email.service.js';
    import { prisma } from '../../config/database.js';
    import { env } from '../../config/env.js';
    import { UnauthorizedError, ForbiddenError } from '../../lib/errors.js';
    ```

    **loginUser(email, password, userAgent?, ipAddress?):**
    1. Find user by email (include check for isActive: true, deletedAt: null)
    2. If user not found, throw UnauthorizedError('Invalid credentials') — same message for not found AND wrong password
    3. Check if account is locked: `user.lockedUntil !== null && user.lockedUntil > new Date()` — if locked, throw ForbiddenError('Account is temporarily locked. Try again later.')
    4. Verify password with verifyPassword(user.passwordHash, password)
    5. On wrong password:
       - Atomically increment failedAttempts AND get the updated value back:
         ```typescript
         const updated = await prisma.user.update({
           where: { id: user.id },
           data: { failedAttempts: { increment: 1 } },
           select: { failedAttempts: true },
         });
         ```
       - Check the RETURNED `updated.failedAttempts` (the post-increment DB value), NOT `user.failedAttempts + 1`:
         ```typescript
         if (updated.failedAttempts >= 5) {
           await prisma.user.update({
             where: { id: user.id },
             data: { lockedUntil: new Date(Date.now() + env.ACCOUNT_LOCKOUT_DURATION_MIN * 60_000) },
           });
         }
         ```
       - Throw UnauthorizedError('Invalid credentials')
    6. On success:
       - Reset failedAttempts to 0, lockedUntil to null, set lastLoginAt to now
       - Generate refresh token with generateRefreshToken()
       - Hash the refresh token using `hashToken(refreshToken)` from token.service.ts
       - Create Session row with: userId, refreshToken (hashed), expiresAt (now + REFRESH_TOKEN_EXPIRY_DAYS), lastActiveAt (now), userAgent, ipAddress
       - Sign access token with signAccessToken({ userId, role, sessionId })
       - Return { accessToken, refreshToken (plaintext), expiresIn: env.ACCESS_TOKEN_EXPIRY_MIN * 60 }

    **IMPORTANT on refresh token storage:** Store the SHA-256 hash of the refresh token in the DB, not the plaintext. The Session model's refreshToken field stores this hash. When looking up a session by refresh token, hash the incoming token first using `hashToken(refreshToken)`, then query: `prisma.session.findUnique({ where: { refreshToken: hashedToken } })`.

    **logoutUser(userId):**
    1. Delete ALL sessions for the user: `prisma.session.deleteMany({ where: { userId } })`
    2. This satisfies AUTH-04: "User can log out, invalidating all current session tokens"

    **refreshSession(refreshToken):**
    1. Hash the incoming refresh token using `hashToken(refreshToken)`
    2. Find session by hashed refresh token, include user
    3. If not found, throw UnauthorizedError('Invalid refresh token')
    4. Check session.expiresAt > now — if expired, delete session and throw UnauthorizedError('Session expired')
    5. Check session.lastActiveAt > now - INACTIVE_SESSION_TIMEOUT_MIN — if inactive too long, delete session and throw UnauthorizedError('Session expired due to inactivity')
    6. Check user.isActive is true — if not, delete session and throw UnauthorizedError('Account deactivated')
    7. Delete old session row
    8. Generate new refresh token, hash it using `hashToken(newRefreshToken)`, create new Session row (token rotation)
    9. Sign new access token
    10. Return { accessToken, refreshToken (new plaintext), expiresIn }

    **requestPasswordReset(email):**
    1. Find user by email (isActive: true, deletedAt: null)
    2. If not found, return silently (prevent email enumeration) — do NOT throw
    3. Generate reset token with generateResetToken() — this already uses hashToken internally
    4. Update user: resetTokenHash = hashedToken, resetTokenExpiry = now + RESET_TOKEN_EXPIRY_MIN
    5. Send email with sendPasswordResetEmail(email, plainToken)
    6. Return void (caller always returns same 200 response)

    **resetPassword(token, newPassword):**
    1. Hash the incoming token using `hashToken(token)`
    2. Find user where resetTokenHash matches AND resetTokenExpiry > now AND isActive is true
    3. If not found, throw UnauthorizedError('Invalid or expired reset token') — same message for all failure cases
    4. Hash new password with hashPassword(newPassword)
    5. Update user: passwordHash = new hash, resetTokenHash = null, resetTokenExpiry = null, failedAttempts = 0, lockedUntil = null
    6. Delete all sessions for this user (force re-login)
  </action>

    - Parse body with forgotPasswordSchema.parse(req.body)

    **resetPassword(req, res):**
    - Parse body with resetPasswordSchema.parse(req.body)
    - Call resetPassword(token, password)

    **Test cases organized by requirement:**

    **AUTH-01: Login with email and master password**
    - `POST /api/auth/login` with valid credentials returns 200, body has accessToken (string), refreshToken (string), expiresIn (number)
    - `POST /api/auth/login` with wrong password returns 401
    - `POST /api/auth/login` with non-existent email returns 401 (same error as wrong password)
    - `POST /api/auth/login` with inactive user returns 401
    - `POST /api/auth/login` with missing/invalid body returns 400

    **AUTH-02: Account lockout after 5 failed attempts**
    - 5 consecutive wrong password attempts: first 4 return 401, 5th returns 401 AND sets lockedUntil
    - 6th attempt (while locked) returns 403 with lock message
    - Successful login resets failedAttempts counter to 0
    - IMPORTANT: Verify lockout uses the post-increment DB value. After the 5th failed attempt, query the user directly and assert `failedAttempts === 5` and `lockedUntil` is not null.

    **AUTH-03: Session expiry after inactivity**
    - `POST /api/auth/refresh` with valid refresh token returns new tokens (200)
    - `POST /api/auth/refresh` after inactivity timeout returns 401
      - To test: create session, then manually set lastActiveAt to past (beyond INACTIVE_SESSION_TIMEOUT_MIN) via prisma.session.update, then call refresh
    - `POST /api/auth/refresh` with expired session (expiresAt in past) returns 401

    **AUTH-04: Logout invalidates ALL sessions**
    - Log in twice to create two sessions
    - `POST /api/auth/logout` with valid auth token from first session returns 200
    - After logout, refresh with EITHER refresh token returns 401 (both sessions deleted)
    - Without Authorization header returns 401

    **AUTH-05: Password reset via email**
    - `POST /api/auth/forgot-password` with valid email returns 200 and calls sendPasswordResetEmail
    - `POST /api/auth/forgot-password` with non-existent email still returns 200 (no enumeration)
    - `POST /api/auth/reset-password` with valid token and new password returns 200
    - After reset, old password no longer works, new password works
    - `POST /api/auth/reset-password` with expired token returns 401
    - `POST /api/auth/reset-password` with already-used token returns 401 (resetTokenHash cleared after use)

    **Testing approach for password reset flow:**
    Since we mock sendPasswordResetEmail, we need to capture the reset token. Two approaches:
    1. Mock sendPasswordResetEmail to store the token argument, then use it in reset-password call
    2. Directly query the user's resetTokenHash from DB after forgot-password, generate the matching plaintext (this is harder)

    Use approach 1: vi.mock the email service module, capture the resetToken argument passed to sendPasswordResetEmail.

    **Important test patterns:**
    - Use `request(app)` from supertest for HTTP calls
    - All test env vars come from vitest.config.ts (JWT_SECRET etc.)
    - Clean up database state between tests to avoid interference
    - Use `beforeAll` to hash the test password once (Argon2 is slow even with test options)
    - For the lockout test, run 5 login attempts in a loop, then verify the 6th is rejected
    - For inactivity test, directly update lastActiveAt via prisma rather than waiting
