    **RED phase — Write failing tests first:**

    Create `src/lib/crypto.test.ts` with the following test cases. The tests need `MASTER_ENCRYPTION_KEY` set in the test environment. At the top of the test file, set `process.env.MASTER_ENCRYPTION_KEY` to a known 64-char hex string (e.g., `'a]'.repeat(32)` — use `'0123456789abcdef'.repeat(4)`) BEFORE importing the crypto module. This avoids Zod env validation issues during testing.

    Alternatively, mock or bypass the env import. The simplest approach: the crypto module should accept the master key as a parameter or read it from env. For testability, make `deriveDEK` use a configurable source. Recommended: have `encrypt` and `decrypt` read from `env.MASTER_ENCRYPTION_KEY` in production, but the test file sets the env var before the dynamic import.

    Test cases (7 tests in one describe block "Envelope Encryption (HKDF + AES-256-GCM)"):
    1. "should encrypt and decrypt a value correctly" — encrypt a string, decrypt it, assert equal
    2. "should produce different ciphertext for the same plaintext (random IV)" — encrypt same value twice, assert encryptedValue and iv differ
    3. "should produce different ciphertext with different key versions" — encrypt with version 1 and 2, assert different, both decrypt correctly
    4. "should fail decryption with tampered ciphertext" — encrypt, mutate encryptedValue, assert decrypt throws
    5. "should fail decryption with wrong key version" — encrypt with version 1, change keyVersion to 99, assert decrypt throws
    6. "should handle empty string" — encrypt empty string, decrypt, assert equals empty string
    7. "should handle unicode and special characters" — encrypt string with accented chars, emoji, special chars, decrypt, assert equal

    Run `npx vitest run` — all tests MUST FAIL (crypto module doesn't exist yet).

    **GREEN phase — Implement the crypto module:**

    Create `src/lib/crypto.ts` following the exact implementation from the research document:
    - Import `createCipheriv`, `createDecipheriv`, `randomBytes`, `hkdfSync` from `node:crypto`
    - Constants: ALGORITHM = 'aes-256-gcm', IV_LENGTH = 12, TAG_LENGTH = 16, KEY_LENGTH = 32, HKDF_HASH = 'sha256'
    - HKDF_SALT: `Buffer.alloc(32, 0)` (fixed zero salt — key versioning provides domain separation)
    - HKDF_INFO_PREFIX: `'kickvault-dek-v'`
    - `deriveDEK(keyVersion: number): Buffer` — uses hkdfSync with master key from env, salt, info prefix + version
    - `EncryptedData` interface: encryptedValue (base64), iv (base64), authTag (base64), keyVersion (number)
    - `encrypt(plaintext: string, keyVersion: number = 1): EncryptedData` — derives DEK, generates random 12-byte IV, encrypts with AES-256-GCM, returns base64-encoded values
    - `decrypt(data: EncryptedData): string` — derives DEK for stored keyVersion, sets auth tag BEFORE update, decrypts, returns UTF-8 string

    CRITICAL encryption order: cipher.update() -> cipher.final() -> cipher.getAuthTag()
    CRITICAL decryption order: decipher.setAuthTag() -> decipher.update() -> decipher.final()

    Run `npx vitest run` — all 7 tests MUST PASS.
  </action>

    Before building Docker, create the initial migration so it exists in the repo:
    1. Ensure PostgreSQL is accessible (either start the db service first with `docker compose up db -d`, or use a local PostgreSQL)
    2. Run: `DATABASE_URL="postgresql://kickvault:kickvault@localhost:5432/kickvault" npx prisma migrate dev --name init`
    3. This creates the `prisma/migrations/` directory with the initial SQL migration
    4. If direct database access is not available, use `npx prisma migrate diff --from-empty --to-schema-datamodel prisma/schema.prisma --script > prisma/migrations/0001_init/migration.sql` (create the directory first with `mkdir -p prisma/migrations/0001_init`)

    **Create custom migration for AuditLog immutability trigger:**
    1. Run: `DATABASE_URL="postgresql://kickvault:kickvault@localhost:5432/kickvault" npx prisma migrate dev --name audit_log_immutable_trigger --create-only`
    2. Edit the generated empty migration SQL file to contain:
       ```sql
       CREATE OR REPLACE FUNCTION prevent_audit_log_mutation()
       RETURNS TRIGGER AS $$
       BEGIN
         RAISE EXCEPTION 'audit_logs table is append-only: % operations are forbidden', TG_OP;
         RETURN NULL;
       END;
       $$ LANGUAGE plpgsql;

       CREATE TRIGGER audit_log_immutable
         BEFORE UPDATE OR DELETE ON audit_logs
         FOR EACH ROW
         EXECUTE FUNCTION prevent_audit_log_mutation();
       ```
