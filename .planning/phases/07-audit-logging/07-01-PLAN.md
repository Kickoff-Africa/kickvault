Modify `src/config/database.ts` to use Prisma `$extends` query component that blocks all update/delete operations on AuditLog.

1. Rename the current `prisma` to `basePrisma` (keep the globalForPrisma caching pattern).
2. Create the extended client:
```typescript
export const prisma = basePrisma.$extends({
  query: {
    auditLog: {
      async update() { throw new Error('AuditLog entries are immutable: update is forbidden'); },
      async updateMany() { throw new Error('AuditLog entries are immutable: updateMany is forbidden'); },
      async delete() { throw new Error('AuditLog entries are immutable: delete is forbidden'); },
      async deleteMany() { throw new Error('AuditLog entries are immutable: deleteMany is forbidden'); },
    },
  },
});
```
3. Also export `basePrisma` (named export) so tests can use it for cleanup via `$executeRawUnsafe('TRUNCATE audit_logs CASCADE')` or direct `basePrisma.auditLog.deleteMany()`.

IMPORTANT: The `$extends` return type is NOT `PrismaClient`. Do NOT type it as PrismaClient. Use `typeof prisma` if any type annotation is needed elsewhere. The globalForPrisma cache should store `basePrisma` (the real PrismaClient), not the extended client.

**Part B: Migrate test cleanup to use basePrisma or TRUNCATE**

In `credentials.test.ts` and `assets.test.ts`:
1. Change the import from `import { prisma } from '../../config/database.js'` to also import `basePrisma`:
   `import { prisma, basePrisma } from '../../config/database.js'`
2. Replace all `await prisma.auditLog.deleteMany()` calls with `await basePrisma.auditLog.deleteMany()` in both beforeEach and afterAll blocks.

This ensures test cleanup bypasses the $extends immutability guard while still using the Prisma ORM (not raw SQL). If the test DB has audit log rows, the DB trigger would block it — but tests clean up in beforeEach so the table should already be empty from prior cleanup. If this causes issues, fall back to `await prisma.$executeRawUnsafe('TRUNCATE audit_logs CASCADE')`.
