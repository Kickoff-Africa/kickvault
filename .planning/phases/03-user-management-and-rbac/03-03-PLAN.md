  <action>
    Follow the EXACT test patterns from src/modules/auth/auth.test.ts:
    - Use `describeWithDb` guard for database-dependent tests
    - Use supertest `request(app)` for HTTP requests
    - Import `setTransporter` from email.service.ts and mock before tests
    - Import `signAccessToken` to create auth tokens for test users
    - Import `prisma` from config/database.ts for direct DB setup/teardown
    - Import `hashPassword` from password.service.ts for creating test users with known passwords

    **Test helper functions:**

    1. `createTestUser(overrides)`: Creates a user directly via prisma.user.create with sensible defaults (email, name, passwordHash from hashPassword('ValidPassword123!'), role: 'MEMBER'). Accepts partial overrides. Returns the user record.

    2. `getAuthToken(user)`: Calls signAccessToken({ userId: user.id, role: user.role, sessionId: 'test-session-id' }) and returns the token string. For tests needing a real session, create a session via prisma.session.create first.

    3. `createSuperAdmin()`: Shorthand for createTestUser({ role: 'SUPER_ADMIN', email: 'admin@test.com' }).

    **Cleanup:** In beforeEach or afterEach, delete all users and sessions to isolate tests. Use prisma.session.deleteMany() then prisma.user.deleteMany() (session first due to FK).

    **Email mock:** In beforeAll, call setTransporter with a mock that captures sent emails (use nodemailer.createTransport({ jsonTransport: true }) or a simple object with sendMail: vi.fn().mockResolvedValue({})).

    **Test groups organized by USER requirement:**

    **USER-01: Invite flow**
    - POST /api/users/invite with SUPER_ADMIN token + valid body (email, name, role) returns 201 with user object
    - Created user has mustChangePassword: true (verify via DB query)
    - Created user has inviteTokenHash set (verify via DB)
    - Invite email was sent (verify mock was called with correct email)
    - POST /api/users/invite with duplicate email returns 409
    - POST /api/users/invite with MANAGER token returns 403
    - POST /api/users/invite with VIEWER token returns 403
    - POST /api/users/:id/resend-invite with SUPER_ADMIN regenerates token and sends email

    **USER-02: Deactivation**
    - POST /api/users/:id/deactivate with SUPER_ADMIN token deactivates user (isActive: false in DB)
    - Deactivation deletes all target user's sessions (verify via DB count)
    - Cannot deactivate self (403)
    - Cannot deactivate another SUPER_ADMIN (403)
    - POST /api/users/:id/deactivate with MANAGER token returns 403
    - Deactivating non-existent user returns 404

    **USER-03: RBAC enforcement**
    - GET /api/users with SUPER_ADMIN token returns 200 with user list
    - GET /api/users with MANAGER token returns 200 (allowed)
    - GET /api/users with MEMBER token returns 403
    - GET /api/users with VIEWER token returns 403
    - GET /api/users without auth token returns 401
    - PATCH /api/users/:id with SUPER_ADMIN can update role
    - PATCH /api/users/:id with MANAGER returns 403 (SUPER_ADMIN only)
    - Last-SUPER_ADMIN safeguard: demoting the only SUPER_ADMIN returns 409

    **USER-04: Password change**
    - POST /api/users/me/password with valid currentPassword + newPassword returns 200
    - After password change, mustChangePassword is false in DB
    - After password change, all sessions EXCEPT current are deleted (create 2+ sessions, verify only current remains)
    - POST /api/users/me/password with wrong currentPassword returns 401
    - POST /api/users/me/password with too-short newPassword returns 400 (Zod validation)
    - POST /api/users/me/password with VIEWER token works (any authenticated user)

    **Login mustChangePassword:**
    - POST /api/auth/login for a user with mustChangePassword: true returns mustChangePassword: true in response body
    - POST /api/auth/login for a normal user returns mustChangePassword: false

    IMPORTANT: For tests requiring a real session (password change session preservation test), create the session via prisma.session.create and use that sessionId in signAccessToken. For simple auth tests, a fake sessionId is fine.

    IMPORTANT: All imports use .js extension. Use `import { describe, it, expect, beforeAll, beforeEach, afterAll } from 'vitest'` if not using globals. Check vitest.config.ts -- globals: true means no import needed.

    IMPORTANT: Do NOT set env vars in the test file. They are configured in vitest.config.ts test.env.
