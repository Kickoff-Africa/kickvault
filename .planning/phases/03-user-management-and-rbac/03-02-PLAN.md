    <!-- ==================== Validation schemas ==================== -->

    **users.validation.ts:**

    Create Zod schemas following the auth module pattern:

    1. `inviteUserSchema`: { email: string().email(), name: string().min(1).max(100), role: z.nativeEnum(Role) } -- import Role from @prisma/client
    2. `updateUserSchema`: { name: string().min(1).max(100).optional(), role: z.nativeEnum(Role).optional() }.refine(data => data.name || data.role, { message: 'At least one field required' })
    3. `changePasswordSchema`: { currentPassword: string().min(1), newPassword: string().min(12, 'Password must be at least 12 characters') }
    4. `listUsersSchema` (query params): { page: z.coerce.number().int().positive().default(1), limit: z.coerce.number().int().min(1).max(100).default(20) }
    5. Export inferred types for each schema.

    <!-- ==================== Service layer ==================== -->

    **users.service.ts:**

    Follow the auth.service.ts pattern (imports at top, exported async functions, Prisma operations, error throwing).

    **Safe user fields constant** (used in all queries returning user data):
    ```typescript
    const SAFE_USER_SELECT = {
      id: true, email: true, name: true, role: true,
      isActive: true, mustChangePassword: true,
      lastLoginAt: true, createdAt: true, updatedAt: true,
    } as const;
    ```

    **Helper function:**
    ```typescript
    async function assertNotLastSuperAdmin(excludeUserId: string): Promise<void> {
      const count = await prisma.user.count({
        where: { role: 'SUPER_ADMIN', isActive: true, deletedAt: null, id: { not: excludeUserId } },
      });
      if (count === 0) throw new ConflictError('Cannot remove the last active SUPER_ADMIN');
    }
    ```

    **Service functions:**

    1. `inviteUser(email, name, role, invitedByUserId)`:
       - Check if email already exists (active or inactive, not soft-deleted): throw ConflictError('Email already in use')
       - Generate temp password via generateTempPassword()
       - Hash temp password via hashPassword()
       - Generate invite token via generateInviteToken()
       - Calculate invite expiry: new Date(Date.now() + env.INVITE_TOKEN_EXPIRY_DAYS * 24 * 60 * 60_000)
       - Create user with: email, name, role, passwordHash (hashed temp password), mustChangePassword: true, inviteTokenHash, inviteTokenExpiry
       - Send invite email via sendInviteEmail(email, tempPassword)
       - Return created user (SAFE_USER_SELECT fields only)

    2. `resendInvite(userId, requestedByUserId)`:
       - Find user by id (not soft-deleted). Throw NotFoundError if not found.
       - Throw ConflictError('User is already active and has logged in') if user.mustChangePassword is false (means they've already completed first login — no pending invite to resend)
       - Generate new temp password + hash it
       - Generate new invite token
       - Update user: passwordHash, inviteTokenHash, inviteTokenExpiry, mustChangePassword: true
       - Send invite email
       - Return updated user (SAFE_USER_SELECT)

    3. `listUsers(page, limit)`:
       - Query users where deletedAt is null
       - Order by createdAt desc
       - Use skip/take pagination: skip = (page - 1) * limit, take = limit
       - Select SAFE_USER_SELECT fields
       - Also get total count
       - Return { users, total, page, limit }

    4. `getUserById(id)`:
       - Find user by id where deletedAt is null, select SAFE_USER_SELECT
       - Throw NotFoundError if not found
       - Return user

    5. `updateUser(userId, data: { name?, role? }, requestedByUserId)`:
       - Find target user (not soft-deleted). Throw NotFoundError if not found.
       - If role change requested:
         - Self-demotion guard: if userId === requestedByUserId && data.role !== 'SUPER_ADMIN', throw ForbiddenError()
         - Cannot demote another SUPER_ADMIN: if target.role === 'SUPER_ADMIN' && userId !== requestedByUserId && data.role !== 'SUPER_ADMIN', throw ForbiddenError()
         - If changing FROM SUPER_ADMIN: call assertNotLastSuperAdmin(userId)
       - Update user with provided fields
       - Return updated user (SAFE_USER_SELECT)

    6. `deactivateUser(userId, requestedByUserId)`:
       - Cannot deactivate self: if userId === requestedByUserId, throw ForbiddenError()
       - Find target user (not soft-deleted, isActive: true). Throw NotFoundError if not found.
       - Cannot deactivate SUPER_ADMIN: if target.role === 'SUPER_ADMIN', throw ForbiddenError()
       - Use prisma.$transaction to atomically:
         a. Update user: isActive = false
         b. Delete all sessions: prisma.session.deleteMany({ where: { userId } })
       - Return updated user (SAFE_USER_SELECT)

    7. `changeOwnPassword(userId, sessionId, currentPassword, newPassword)`:
       - Find user by id (not soft-deleted, isActive). Throw NotFoundError if not found.
       - Verify currentPassword against user.passwordHash using verifyPassword. Throw UnauthorizedError('Current password is incorrect') if wrong.
       - Hash newPassword via hashPassword
       - Update user: passwordHash, mustChangePassword: false
       - Delete all sessions EXCEPT current: prisma.session.deleteMany({ where: { userId, id: { not: sessionId } } })
       - Return void

    IMPORTANT: Import ConflictError from '../../lib/errors.js'. Import NotFoundError, ForbiddenError, UnauthorizedError as needed. Use .js extensions on ALL imports.

    **users.controller.ts:**

    Follow the thin controller pattern from auth.controller.ts:
    - Parse body/params/query with Zod schema
    - Call service function
    - Return JSON response with appropriate status code

    Controllers:
    1. `invite` (POST /api/users/invite): parse body with inviteUserSchema, call inviteUser(email, name, role, req.user!.id), return 201 with { user }
    2. `list` (GET /api/users): parse query with listUsersSchema, call listUsers(page, limit), return 200 with { users, total, page, limit }
    3. `getById` (GET /api/users/:id): get id from req.params, call getUserById(id), return 200 with { user }
    4. `update` (PATCH /api/users/:id): parse body with updateUserSchema, get id from params, call updateUser(id, body, req.user!.id), return 200 with { user }
    5. `deactivate` (POST /api/users/:id/deactivate): get id from params, call deactivateUser(id, req.user!.id), return 200 with { user }
    6. `resendInvite` (POST /api/users/:id/resend-invite): get id from params, call resendInvite(id, req.user!.id), return 200 with { user }
    7. `changePassword` (POST /api/users/me/password): parse body with changePasswordSchema, call changeOwnPassword(req.user!.id, req.sessionId!, currentPassword, newPassword), return 200 with { message: 'Password changed successfully' }

    Handle Zod parse errors the same way as auth.controller.ts (parseBody helper or try/catch converting ZodError to ValidationError).

    **users.routes.ts:**

    Create Express Router with prefix '/api/users'. All routes use authenticate middleware. Role-restricted routes also use requireRole.

    Route definitions (ONLY these — no contradictory table):
    ```
    POST   /api/users/me/password         authenticate                           -> changePassword  (any authenticated)
    POST   /api/users/invite              authenticate, requireRole()             -> invite          (SUPER_ADMIN only)
    GET    /api/users                     authenticate, requireRole('MANAGER')   -> list            (SUPER_ADMIN, MANAGER)
    GET    /api/users/:id                 authenticate, requireRole('MANAGER')   -> getById         (SUPER_ADMIN, MANAGER)
    PATCH  /api/users/:id                 authenticate, requireRole()             -> update          (SUPER_ADMIN only)
    POST   /api/users/:id/deactivate      authenticate, requireRole()             -> deactivate      (SUPER_ADMIN only)
    POST   /api/users/:id/resend-invite   authenticate, requireRole()             -> resendInvite    (SUPER_ADMIN only)
    ```

    IMPORTANT: /api/users/me/password MUST be defined FIRST (before any /:id routes) to prevent 'me' being captured as an :id param.

    requireRole() with NO arguments = only SUPER_ADMIN can access (SUPER_ADMIN auto-passes; empty allowedRoles rejects all other roles).
    requireRole('MANAGER') = SUPER_ADMIN and MANAGER can access.
